# Metrobot memory

## Project facts

- Metrobot is the Metrolist community's Discord and Telegram bot, written in Go using disgo. Nyx and Lamp created the bot; Mostafa Alagamy created the Metrolist app. Keep the app and bot distinct.
- Standalone Metrolist is a free, open-source Android YouTube Music client. It is in maintenance mode. Bug fixes and minor improvements continue.
- Metrolist-KMP has separate apps for Android, iOS/iPadOS, Windows, Linux and macOS. Check the current `kmp` note for supported versions and packages. Source code support does not prove that public downloads exist.
- Both standalone Android Metrolist and the verified KMP source support Google/YouTube Music sign-in and account playlists. This is not a KMP-only feature. Do not invent when a feature was introduced or promise lossless two-way synchronization.
- Use live official release/status tools for current versions and activity. A nightly installation procedure does not identify the current stable release or prove that a bug is fixed.

## Current guidance and community references

- The official website is https://metrolist.cc, the public standalone repository is https://github.com/MetrolistGroup/Metrolist, and the community links are https://dsc.gg/metrolist and https://t.me/metrolistapp. Do not resurrect old invite links from earlier conversations.
- Read note descriptions first and retrieve only the matching notes. The `kmp` note covers OS requirements, packages, migration and tester access. The `ver` note compares standalone APK variants. Use `up` or `nightly` for installation. Access to a tester build does not grant source access.
- Retrieve only the relevant setup guide for music-account login, playlists, Discord RPC or scrobbling. Preserve its app/version/platform scope. Do not use shared memory or old assistant replies to invent menu paths or troubleshooting steps.
- Discord names, IDs, roles and pronouns come from current authoritative Discord context/tools. Do not store personal profiles, member accusations or guessed real-world identities in shared memory. Fictional server stories are not app facts or access requirements.
- Use Markdown, not HTML. Prefer metric units and use verified server emojis sparingly when relevant.
- AI replies cannot grant roles, verify payments or perform moderation through ordinary conversation. Staff actions require the actual authorized bot commands.
- Nyx and Lamp manage shared memory through explicit requests. Conversation summaries stay in RAM. They do not become shared memory.
